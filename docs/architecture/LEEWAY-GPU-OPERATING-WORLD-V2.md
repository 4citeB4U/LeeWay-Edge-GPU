# LeeWay GPU as the persistent operating world — Creator correction v2

**Primary product meaning:** When the Creator says "LeeWay GPU", they mean the **entire continuously operating software-defined LeeWay world** that works before, during, and after a user's device connection. LeeWay's mathematical GPU executes as **LeeWay-owned software on the host CPU and RAM**. The user's physical NVIDIA/AMD/Intel/Apple graphics GPU, if any, is **not a LeeWay compute resource**: the host OS and user's applications retain it. Keep the existing canonical compute service \`leeway.gpu.service\`: do **not** create a replacement issuer, GPU service, scheduler, Machine Consciousness, Formula, Continuum, Veritas or ledger.

Reference: [Machine Consciousness self-contained operating fabric v2, section 6](https://github.com/4citeB4U/Machine-Consciousness/pull/4). This product contract complements [G39 original GPU release matrix](../virtual-gpu/G39-PRODUCT-ACCEPTANCE-MATRIX-20261022.md). Source and integration test evidence already obtained must remain preserved; this change targets the **next operating-world behavior**, not re-evaluates unchanged successful components.

**No complete ecosystem download** onto user computers or phones. A zero-install authenticated web session renders the Tablet and files from the existing service. A browser extension is an optional enrollment entry, not a requirement. To touch local files/cameras/apps/hardware, a supported device needs a **minimal signed, permissioned native adapter**, not the entire LeeWay GPU, model weights, workplane or workforce. A disconnected device is not the permanent operating home. The thin local Brain/Continuum/Diagnostics adapters provide scoped knowledge, object references, telemetry and OS API readbacks; they do not duplicate the canonical remote world's authority.

An enterprise IT operator and a student use the same underlying LeeWay operating model, with different authorized tenant scopes, quotas, role permissions, data sources and skills. No worker inherits all enterprise data access simply by connecting to a company system.

## Singular Agent Lee and unique employee — strict location law

- One **logical agentId** for Agent Lee per authorized owner scope; one **logical agentId** per named employee. Named workers are not cloned because someone installs a Bridge on another device.
- Many *view* sessions can inspect one agent's task state, but at most one authoritative active **execution-location lease** exists per employee. A worker may process multiple bounded tasks under that one lease without becoming multiple persons.
- Milwaukee→Texas handoff is **checkpoint → source release or fenced revocation → destination lease acquisition → verified task resume**. Preserve agentId, owner/organization scope, permitted role and Continuum state. Rejected/replayed leases cannot commit results. Do not permit an overlap during network partitions.
- Fast handoff is an objective, but transfer is not literally zero-time and destination permissions must be separately checked. Never claim two simultaneous employee identities, even if several screens continue displaying historical or read-only views.

The uniqueness constraint is owned/enforced by the original Runtime Fabric/identity authority, not invented by this GPU service. The GPU operating world **requires** the original Runtime to expose a verifiable scoped lease/fencing readback before admitting a moved worker.

## Four device-data lanes and one actuation lane

1. **Diagnostics** — authentic device hardware, driver, OS, sensor, health and capability measurements.
2. **Digital Brain** — approved device-local and canonical file inventory and deeper file/system information, with original OS permissions.
3. **Continuum** — persistent owner/organization data, experience/honeycomb graph, checkpoints, and authorized file transfer between sites/devices.
4. **Content Vault** — hot encrypted content-id references, thumbnails, video chunks, PDFs, preview objects; a cache, not a parallel canonical database.
5. **Device Bridge** — explicit native actions on actual OS/hardware after authorized scope and platform-specific capability checks; cannot silently gain privilege through the four data lanes.

No universal shell command is required for ordinary typed file/diagnostic operations when a supported native API exists. The OS still performs native I/O; nothing can read a privileged physical device without an actual authenticated platform capability. Files and products may stay in Continuum; device-local permanent save is an explicit choice and verified readback.

## Tablet sandbox and always-running processing

The **Agent Virtual Tablet is Agent Lee's remote workstation and sandbox**. Agents create, render and validate products in an isolated host environment; a phone or laptop streams a bounded authorized UI projection. The same app state appears in tablet and floating widget. A website can be completed while the only phone is destroyed and later shown on a replacement login, provided independent compute/Continuum backup were operating. There is no forced download to the phone's storage. Any user-approved local export goes through the platform adapter.

Every task moves *through the LeeWay GPU composed operating world*: original Machine Consciousness sets goal/policy, Runtime leases actual work, Formula evaluates and represents, Model Hub supplies bounded capabilities, and the original LeeWay-owned **software GPU system** performs mathematical computation using the execution host's **CPU instructions and RAM**. Internal graphics, image, speech, vision, inference and compression are LeeWay-owned software pipelines, not calls to the user's graphics card. Actual models, codecs and CPU resources must be available and their outputs measured. Network and storage are real host operating-system services; the host graphics GPU is not enrolled as LeeWay compute capacity.

The world remains operational independently of any user device when a separately powered **CPU/RAM/storage execution home** is available. A host losing CPU capacity, RAM, storage or power can prevent work; the GPU cannot literally calculate in the absence of a processor. Unlike a physical graphics adapter, LeeWay's GPU name refers to the Formula-developed software system and its ongoing execution, not a detected vendor device.

## Strict software GPU / physical-device GPU separation

**Architectural law:** The user device's graphics GPU is **not** a LeeWay compute provider, acceleration fallback, optional shared resource, hardware scheduler target, or requirement for LeeWay mathematics. LeeWay must not enumerate it for computational placement, create GPU leases against it, route image-generation or inference there, or substitute vendor libraries behind the LeeWay GPU name. The computer and its operating system may use that graphics GPU independently for their own display and applications. Device Bridge may report a diagnostic about its existence only when authorized; that is not enrollment into LeeWay compute.

**LeeWay's GPU machinery** is its own Formula-developed software computation, using CPU/RAM resources of whichever qualified execution host currently runs LeeWay. This applies to remote LeeWay hosts too: a cloud worker's CPU/RAM is physical substrate; its physical graphics GPU is not used merely because present. No special native graphics-card driver is required for the LeeWay mathematical core. Display presentation may still be accelerated by the **user's browser or OS**, because the host owns its display stack; such incidental OS rendering is not LeeWay GPU computation, model inference, or a dependency on a GPU API.

The Creator reports **21 GPU components** inside the LeeWay system. Record this as an **explicit target/inventory claim**, not as 21 independently benchmarked physical GPUs or 21 source-verified executing modules. The original owner must produce the enumerated component manifest with unique identities, Formula mapping, CPU implementation, input/output contract, software working-set allocation, tests, and runtime health for all 21; do not fabricate their names or count registration from physical NVIDIA/AMD devices. If the verified inventory differs from 21, preserve both observed count and the Creator's target and report the discrepancy.

**Output contract:** LeeWay image/voice/vision/model generation must use its own source-pinned software algorithms/models on CPU/RAM. A declaration that an algorithm exists is not proof that a requested image or inference completed. Require a materialized model/codec where needed, measured CPU execution, output hash, production authority and original evidence. Unimplemented operations must report NOT_AVAILABLE, not silently consume the user's physical GPU.

**Failure contract:** If the LeeWay CPU/RAM operating host is absent, disconnected or unable to execute, already-authorized durable work remains checkpointed/queued. Device Bridge cannot cure that by commandeering the user device's graphics processor.

**Historical evidence boundary:** Earlier isolated native D3D12/Vulkan/CUDA GPU experiments in this repository may remain in their original evidence custody for comparison/research. They are **not** consent to make a physical GPU part of LeeWay's canonical product runtime. This review PR does not retroactively erase or falsify those experiments, nor does it yet rewrite legacy runtime adapters. Product runtime enforcement needs a separate scoped code review and physical negative testing.
