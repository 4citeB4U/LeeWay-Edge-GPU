# LeeWay GPU as the persistent operating world — Creator correction v2

**Primary product meaning:** When the Creator says "LeeWay GPU", they mean the **entire continuously operating software-defined LeeWay world** that works before, during, and after a user's device connection. The underlying physical GPU/CPU/PCIe is its substitutable computing resource, not its identity. Keep the existing canonical compute service \`leeway.gpu.service\`: do **not** create a replacement issuer, GPU service, scheduler, Machine Consciousness, Formula, Continuum, Veritas or ledger.

Reference: [Machine Consciousness self-contained operating fabric v2, section 6](https://github.com/4citeB4U/Machine-Consciousness/pull/4). This product contract complements [G39 original GPU release matrix](../virtual-gpu/G39-PRODUCT-ACCEPTANCE-MATRIX-20261022.md). Source and integration test evidence already obtained must remain preserved; this change targets the **next operating-world behavior**, not re-evaluates unchanged successful components.

## World versus a device

| Persistent LeeWay world | Accessing device |
| --- | --- |
| Already running on independently available compute/storage | Existing Windows, Linux, Apple, Android OS retained |
| One owner-scoped Agent Lee, named workers and authoritative task history | Any number of authorized viewing screens; no cloned agent |
| Runtime Fabric's durable work supervision and lease/fencing | Thin signed Device Bridge only for permitted native capabilities |
| Model Hub, Formula, GPU compute, LDWMD, Voice/Live/Vision/RTC, Continuum and original governance | Digital Brain scoped file access, Continuum scoped synchronization, Diagnostics host facts and Content Vault quick previews |
| Virtual Tablet as remotely executing sandbox, previews and product workspace | Browser-first remote rendering; optional explicit native product export |

**No complete ecosystem download** onto user computers or phones. A zero-install authenticated web session renders the Tablet and files from the existing service. A browser extension is an optional enrollment entry, not a requirement. To touch local files/cameras/apps/hardware, a supported device needs a **minimal signed, permissioned native adapter**, not the entire LeeWay GPU, model weights, workplane or workforce. A disconnected device is not the permanent operating home. The thin local Brain/Continuum/Diagnostics adapters provide scoped knowledge, object references, telemetry and OS API readbacks; they do not duplicate the canonical remote world's authority.

An enterprise IT operator and a student use the same underlying LeeWay operating model, with different authorized tenant scopes, quotas, role permissions, data sources and skills. No worker inherits all enterprise data access simply by connecting to a company system.

## Singular Agent Lee and unique employee — strict location law

- One **logical agentId** for Agent Lee per authorized owner scope; one **logical agentId** per named employee. Named workers are not cloned because someone installs a Bridge on another device.
- Many *view* sessions can inspect one agent's task state, but at most one authoritative active **execution-location lease** exists per employee. A worker may process multiple bounded tasks under that one lease without becoming multiple persons.
- Milwaukee→Texas handoff is **checkpoint → source release or fenced revocation → destination lease acquisition → verified task resume**. Preserve agentId, owner/organization scope, permitted role and Continuum state. Rejected/replayed leases cannot commit results. Do not permit an overlap during network partitions.
- Fast handoff is an objective, but transfer is not literally zero-time and destination permissions must be separately checked. Never claim two simultaneous employee identities, even if several screens continue displaying historical or read-only views.

The uniqueness constraint is owned/enforced by the original Runtime Fabric/identity authority, not invented by this GPU service. The GPU operating world **requires** the original Runtime to expose a verifiable scoped lease/fencing readback before admitting a moved worker.

## Four device-data lanes and one actuation lane

1. **Diagnostics** — authentic device hardware, driver, OS, sensor, health and capability measurements.
2. **Digital Brain** — approved device-local and canonical file inventory and deeper file/system information, with original OS permissions.
3. **Continuum** — persistent owner/organization data, experience/honeycomb graph, checkpoints, and authorized file transfer between sites/devices.
4. **Content Vault** — hot encrypted content-id references, thumbnails, video chunks, PDFs, preview objects; a cache, not a parallel canonical database.
5. **Device Bridge** — explicit native actions on actual OS/hardware after authorized scope and platform-specific capability checks; cannot silently gain privilege through the four data lanes.

No universal shell command is required for ordinary typed file/diagnostic operations when a supported native API exists. The OS still performs native I/O; nothing can read a privileged physical device without an actual authenticated platform capability. Files and products may stay in Continuum; device-local permanent save is an explicit choice and verified readback.

## Tablet sandbox and always-running processing

The **Agent Virtual Tablet is Agent Lee's remote workstation and sandbox**. Agents create, render and validate products in an isolated host environment; a phone or laptop streams a bounded authorized UI projection. The same app state appears in tablet and floating widget. A website can be completed while the only phone is destroyed and later shown on a replacement login, provided independent compute/Continuum backup were operating. There is no forced download to the phone's storage. Any user-approved local export goes through the platform adapter.

Every task moves *through the LeeWay GPU composed operating world*: original Machine Consciousness sets goal/policy, Runtime leases actual work, Formula evaluates and represents, Model Hub supplies bounded capabilities, and the existing GPU compute service may accelerate eligible workloads. CPU, RAM, disk, network and PCIe perform necessary physical operations; not every operation runs on GPU silicon. The world is persistent, while individual hardware utilization may change. If the last powered compute/storage resource disappears, active work cannot continue and must correctly enter recovery/blocked state.
